    e = remove the next event from Q
    if e is a start:
        insert its segment into T
    if e is an end:
        remove its segment from T
    if e is a crossing:
        verify the pair is still scheduled, active, and adjacent
        if valid, report the crossing and swap the pair in T
    cancel crossing events for destroyed adjacencies
    check newly adjacent pairs
    schedule their strictly future crossings, avoiding duplicates
    record the resulting state for visualization

      About this project

      Charlie Solari - CSCI 716

      This application illustrates how a plane sweep finds intersections among line segments. It connects each event to the event queue, the active segment order, and the neighbor checks performed by the algorithm.

      Problem and assumptions

      The input is a set of line segments in the plane; the output is the set of intersection points. The explanation below assumes nonzero, nonvertical segments, no overlapping segments, no endpoint contacts, no three segments meeting at one point, and distinct x-coordinates for all events.

      How the sweep works

      A vertical line moves from left to right. The event queue contains endpoints and discovered future crossings. The status structure contains active segments in top-to-bottom order. Between events, this order does not change.

      • At a start endpoint, insert the segment and check its immediate neighbors.
      • At an end endpoint, remove the segment and check the pair exposed across the gap.
      • At a crossing, report the point, swap the crossing pair, and check the new outer neighbors.

      Here the Python status structure is an AVL tree, and the event queue is an indexed min-heap. Crossing events are canceled when their segments are no longer adjacent. A pair is checked again if it becomes adjacent later.

      The standard event cases are described in MIT's sweep-line lecture notes; this implementation sweeps left to right.

      Why checking neighbors is enough

      Claim. Two segments crossing at an isolated interior point p are adjacent immediately before the sweep reaches p.

      Proof sketch. Choose a sufficiently small disk around p that contains no endpoints and meets no segments other than the crossing pair. Such a disk exists because the input is finite and no third segment contains p. Just to the left of p, both segments meet the sweep line inside this disk. The vertical interval between those two intersections is also inside the disk, so no third segment can lie between them. Therefore they are neighbors.

      This is the neighbor lemma used in David Mount's computational geometry notes. It does not mean that intersecting segments are neighbors throughout the sweep.

      Why no crossing is missed

      Maintain three invariants after each event:

      1. T gives the active order immediately to the right of the event.
      2. Each adjacent pair with a strictly future crossing has that crossing queued.
      3. All crossings at or to the left of the processed event have been reported.

      Initially T is empty and there are no earlier crossings. An insertion, removal, or crossing changes only local adjacencies; updating those pairs preserves the first two invariants. Suppose a crossing were missed. Immediately before it, the neighbor lemma makes its segments adjacent. Their last adjacency change must therefore have scheduled it, and it remains queued while they stay adjacent. The queue cannot advance past it without processing it, contradicting the supposed omission. Reported points come from actual segment-intersection tests, so no false points are introduced.

      For the event-invariant approach, see Carola Wenk's plane-sweep slides.

      What the example demonstrates

      When B starts, the A/B crossing is scheduled. C then starts between A and B, canceling that event. When C ends, A and B become neighbors again and their crossing is rescheduled. At (5.5, 5.3), the algorithm reports the point and swaps their order. Canceling an event changes the queue, not the geometric input.

      Running time

      Let n be the segment count and k the number of crossings under the assumptions above. There are 2n endpoint events and k crossing events. Each event changes a constant number of adjacencies. Balanced-tree and indexed-heap operations cost O(log n), giving O((n + k) log n) time under constant-cost geometric arithmetic. Immediate cancellation keeps only O(n) pending neighbor crossings; the working structures use O(n) space, excluding O(k) stored output.

      This is the standard bound discussed in MIT's lecture notes. Dense inputs can have k = Θ(n2), so this bound does not promise an improvement over brute force on every input.

      Applications

      Finding segment intersections is useful when geometric data needs to be combined or checked:

      • Geographic information systems: overlay map layers, such as road and river networks, and find where their line segments cross.
      • Computer-aided design: find intersections between polygon boundaries as a step toward computing unions or intersections of shapes.
      • Robotics: intersection tests can help determine whether a proposed path crosses obstacle boundaries in a planar model.
